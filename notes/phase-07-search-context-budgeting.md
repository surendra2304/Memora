# Phase 7 — Search, context assembly and token budgeting

**Status:** Complete. Static review plus one synthetic, local-only budget probe; no external service was contacted. No source changed.

## Search composition

- [FACT] `SearchService.hybrid_search` combines (1) deterministic hashed-vector retrieval, (2) lexical matching, (3) one-hop graph-neighbor boosts, (4) reciprocal-rank fusion, an entity substring boost, time/trust/policy filtering, then deterministic sorting (`core/memory/search_service.py:111-287`; `core/memory/graph_service.py:243-264`).
- [FACT] The checked-in retrieval weights are dense 0.6, “bm25” 0.3, graph 0.1; `rrf_k` is 60 and entity boost defaults to 0.1 (`config/retrieval_config.json`; `core/memory/retrieval_config.py:20-58,86-104`). The fallback weights are 0.50/0.35/0.15. The search service consumes method weights but does not consume the configured salience/recency/importance factor weights (`core/memory/retrieval_config.py:60-110`; `rg` found no production `ranking_factor()` caller).
- [FACT] The “BM25” path is not BM25 or database full-text search: it loads all matching-tenant, allowed-state rows with `.all()`, scans content strings in Python, and scores query terms by substring hits / token count (`core/memory/search_service.py:132-162`). The graph contribution is direct-neighbor expansion, not a multi-hop walk (`core/memory/graph_service.py:243-264`). [INFERENCE] Runtime/latency can grow with the tenant's candidate corpus despite a small result limit.
- [FACT] `EmbeddingGenerator` creates a deterministic signed feature-hash vector (SHA-256 token buckets, sublinear term frequency and L2 normalization), not a pretrained semantic embedding (`storage/vector/embedding.py:22-86`). It defaults to 384 dimensions; `Settings.VECTOR_DIMENSION` is 1536 and has no production-code references, and the adapter does not create/configure the collection (`core/config.py:27-30`; `storage/vector/qdrant_adapter.py:27-41`). [HYPOTHESIS] A separately provisioned Qdrant collection dimension may be incompatible; external Qdrant was not available or tested.
- [FACT] The semantic vector query requests `limit * 3` results at a hard-coded score threshold of 0.30 and tenant filter (`core/memory/search_service.py:114-121`; `storage/vector/qdrant_adapter.py:188-234`).
- [FACT] Keyword matching is applied to `namespace_path` and `memory_types` before lexical scanning, but the final union query applies tenant/lifecycle/user/agent/workspace/task filters and omits `namespace_path` and `memory_types` (`core/memory/search_service.py:132-150,173-191`). Vector and graph candidates can therefore survive the final stage despite those requested filters. [INFERENCE] Search clients treating these parameters as hard constraints may receive records from other accessible namespaces or types; confirm with a focused Phase 12 probe.
- [FACT] Search checks temporal validity and provenance trust, then calls `PolicyEngine` for each returned candidate when an actor row exists (`core/memory/search_service.py:194-233`). If the actor cannot be resolved, the policy branch is skipped (`:104-109,221-233`). The authenticated `/v1/memories/search` endpoint passes an actor name but no tenant (`apps/api/routers/v1_memories.py:354-375`); startup does not seed agents except through optional Turso import (`apps/api/main.py:148-157`). [INFERENCE] On a fresh deployment with a valid credential but no registered agent row, this search path can return default-tenant candidates without namespace policy. The direct search endpoint also resolves same-named agents without tenant scoping. Phase 12 should confirm both safely.
- [FACT] `MemoryService.query_memories` instead scopes to the query tenant (overridden by resolved actor tenant), filters expiry and valid states, supports escaped any-term SQL `ILIKE` matching capped at 24 terms, and policy-filters accessible results before pagination (`core/memory/service.py:33-65,221-329`). Unlike `SearchService`, it filters `expires_at` but not `valid_from`/`valid_until` (`:265-273`).

## Ranking and context construction

- [FACT] `ContextReranker` first weights relevance by confidence, exponential freshness (60-day half-life), importance and type multipliers (1.45 for EXPERIENCE; 1.15 for PROCEDURAL), then blends a cross-encoder score at 0.65 with coarse relevance (`core/memory/context/reranker.py:162-269`).
- [FACT] Despite the “neural cross-encoder” names, the remote `sentence-transformers` model is opt-in (`MEMORA_USE_REMOTE_CROSS_ENCODER`, default `false`); otherwise scoring is a local deterministic token/solution-bridge heuristic (`core/memory/context/reranker.py:19-75,77-133`).
- [FACT] `ContextBuilderService` resolves/creates its target actor, retrieves up to `max_candidates`, and retries on any retrieval exception with vector weight 0, keyword 0.85 and graph 0.15 (`core/memory/context/builder.py:89-139`). `SearchService` invokes vector search unconditionally, even when vector weight is zero (`core/memory/search_service.py:91-120`). [INFERENCE] If Qdrant raises in production, the retry repeats that vector call and is not a true vector-independent fallback; this failure path was not runtime-tested.
- [FACT] Predictive prefetch examines up to 200 tenant-local EXPERIENCE/PROCEDURAL rows, active or verified, sorted by importance; it appends a row on any meaningful query-token overlap or importance >=0.95 (`core/memory/context/builder.py:142-188`). It filters optional user ID but not the requested namespace, workspace or task (`:145-161`), so those scope constraints are not consistently applied to the prefetch. A later per-item read-policy check runs (`:196-210`), but policy is namespace-level.
- [FACT] The context builder runs the reranker, then a fail-closed read policy filter, then budgeting; graph edges are returned only when both endpoints are included memory IDs (`core/memory/context/builder.py:190-249`). Context response includes a textual summary, memory records/provenance and graph edges; `ContextBundle.to_dict()` includes `is_degraded` (`:49-64`). The FastAPI `ContextBundleResponse` omits that field (`apps/api/routers/v1_context.py:27-39`); [INFERENCE] response-model serialization drops the structured degradation flag even though the summary may contain a warning.

## Budgeting and privacy

- [FACT] Token count is estimated as `max(1, int(characters / 4))`, not by a model tokenizer (`core/memory/context/budgeter.py:179-184`). On budget overflow, records are clustered by namespace and each cluster receives at least 20 target tokens (`:227-253`). A single-record cluster bypasses both remote and local summarization/truncation and returns its original text (`:85-87`); the caller does not enforce a total cap on summaries (`:253-270`).
- [FACT — local verification] A synthetic 8,000-character, one-record item with a 100-token limit returned unchanged (8,000 characters), reported 2,000 tokens and strategy `summarized`. Re-run output is recorded in this note's evidence: `input_chars=8000`, `budget=100`, `reported_tokens=2000`, `returned_chars=8000`. This used `.venv` locally; singleton behavior returns before any external-client branch.
- [FACT] The budget counter sums memory content only (`core/memory/context/builder.py:212-222`), while the response also includes per-memory IDs/metadata/provenance, graph edges and a summary (`:228-289`). [INFERENCE] The advertised `token_budget` is not a limit on the serialized response as a whole. Additionally, `tokens_per_cluster`'s 20-token floor and unbounded returned provider summaries can push multi-cluster output past the nominal budget (`core/memory/context/budgeter.py:236-270`).
- [FACT — privacy] When more than one memory is summarized and `OPENAI_API_KEY` is present, raw memory IDs/content and the query are sent to OpenAI `gpt-4o-mini`; otherwise an `ANTHROPIC_API_KEY` can send raw memory content to Claude Haiku (`core/memory/context/budgeter.py:89-130`). The fallback without these credentials is local deterministic sentence extraction/deduplication and character truncation (`:132-176`). **No API keys were used and no memory content was transmitted externally during this review.** The code path is conditional, not exercised.
- [FACT] `similarity_dedup_threshold` is an unused `fit_to_budget` argument; compaction groups by namespace and removes exact normalized duplicate sentences, not near-duplicate semantic facts (`core/memory/context/budgeter.py:187-193,230-234,145-160`).

## Exit check

- [FACT] The implementation is hybrid in naming and scoring, but vector embeddings are local feature hashing, lexical ranking is Python substring overlap, graph expansion is one hop, and default reranking is heuristic. Configured “BM25” and ranking factors overstate the algorithms currently exercised by these paths.
- [FACT] One local runtime probe reproduced a severe context-budget overrun; no network, external model, Qdrant or production service was contacted. Phase 7 is complete; next is persistence, schema/migrations, and deletion convergence.
