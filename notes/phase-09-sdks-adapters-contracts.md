# Phase 9 — SDKs, adapters and cross-agent contracts

**Status:** Complete (static review). No source changed and no SDK call was sent to the default hosted URL.

## Inventory and wiring

- [FACT] There are two distinct HTTP client surfaces: `sdk/memora_client.py` plus `sdk/cloud_fallback.py`, and `adapters/base_adapter.py` plus specialized Friday, Forge, Sentinel and AI Universe adapters (`sdk/`; `adapters/`). The adapter registry/config describes 8 identities (`friday`, `forge`, `futuris`, `intelx`, `mt5`, `nexus`, `sentinel`, `ai_universe`) (`adapters/adapter_config.yaml`; `adapters/adapter_registry.py:16-27,93-95`). The API credential map has 9 names: `friday`, `inference`, `stratex`, `intelx`, `futuris`, `cortex`, `forge`, `sentinel`, `memora` (`apps/api/dependencies.py:57-67`). **Only five names overlap.** Roles in YAML are adapter metadata, not server-side authorization roles.
- [FACT] `EcosystemMemoryAdapter` is a separate DTO/contract builder that returns `MemoryRecordCreate` objects; its methods cover peer-specific memory shapes (`adapters/ecosystem.py:11-82,84-120,122-188,190-280`). `memora_upgrade/` is a separate standalone reference engine (models, policy, ingestion, retrieval, store, cache, graph, etc.) exported by `memora_upgrade/__init__.py:6-32`; it is not the API's storage/runtime implementation.
- [FACT] No production imports of `sdk/`, `adapters/` or `memora_upgrade/` from `apps/`, `core/` or `storage/` were found in the Phase 2 import scan. README itself calls them unwired library surfaces (`README.md:70-75`). Their behavior is therefore optional integration behavior, not automatically active when the API starts.

## Credentials, URL defaults and error semantics

- [FACT] `BaseAgentAdapter` defaults to `http://localhost:8000`, sends `X-Agent-Name`, and sends `X-API-Key` plus Bearer only if the caller explicitly supplies `api_key`; neither registry nor adapter config loads per-agent keys from the environment (`adapters/base_adapter.py:39-75`; `adapters/adapter_registry.py:97-131`). An unconfigured adapter request is therefore missing the credential required by the server.
- [FACT] The main `sdk.MemoraClient` defaults to `https://memora-cavc.onrender.com`, stores `api_key`/`MEMORA_API_KEY`, but its `_headers()` uses only the method argument or `{AGENT}_API_KEY`; `rg` confirms `self.api_key` is otherwise never read (`sdk/memora_client.py:28-53`). [INFERENCE] Passing `api_key=` to the constructor does not authenticate ordinary SDK operations; they require the per-agent environment variable or a lower-level explicit header path. The separate `sdk.cloud_fallback.MemoraClient` does use `self.api_key` as a fallback (`sdk/cloud_fallback.py:15-36`).
- [FACT] The main SDK and cloud fallback client use `urllib.request` with finite timeouts. The main SDK has private local SQLite helpers but defaults `local_db_path` to empty; normal public operations make HTTP requests and do not invoke those helpers as an outage fallback (`sdk/memora_client.py:35-42,176-280,306-374,407-660`; `sdk/cloud_fallback.py:12-53`). Some read methods return `[]`/empty prompt on HTTP failure while write/event methods return error objects, so “no results” and “service unavailable” are not consistently distinguishable (`sdk/memora_client.py:251-304,345-400`).

## Route and identity contract discrepancies

- [FACT] Both `sdk.MemoraClient.learn_from_outcome` and `sdk.cloud_fallback.MemoraClient.learn_from_outcome` call `POST /v1/memories/learn-outcome` with flat `agent_name`/`task_name`/`status` fields (`sdk/memora_client.py:306-343`; `sdk/cloud_fallback.py:68-73`). The mounted implementation is `POST /v1/memories/learn-experience`, expects `LearnExperienceRequest` with `agent_id`, `namespace_path` and an `outcomes` list (`apps/api/routers/v1_memories.py:326-352`; `core/memory/experience_service.py:19-30`). [FACT] These SDK methods cannot use the current endpoint/path/body contract as written.
- [FACT] `BaseAgentAdapter.get_context()` places `agent_id=self.agent_name` in the request body (`adapters/base_adapter.py:187-206`), and `v1_context` chooses body `agent_id` over the authenticated header principal (`apps/api/routers/v1_context.py:41-63`). Friday's delegation helper intentionally sets that body field to a sub-agent identity while making the HTTP call with the Friday credential (`adapters/friday/adapter.py:74-100`). This reuses the body-selected principal behavior documented in Phase 4.
- [FACT] `BaseAgentAdapter.get_namespace_policy()` accepts either an ID or URI path and appends it raw to `/v1/namespaces/{namespace_id}/policy` (`adapters/base_adapter.py:264-272`). The route parameter is a single ordinary path segment and performs ID-then-path lookup (`apps/api/routers/v1_namespaces.py:14-31`). [INFERENCE] A raw `memora://owner/private` path contains slash separators and is not safely represented as that one segment; callers should use namespace IDs or URL-encode and verify routing. The endpoint still only requires an authenticated name, not a policy authorization decision (Phase 4).
- [FACT] `BaseAgentAdapter` passes namespace path to GET search and uses `/v1/context` for context (`adapters/base_adapter.py:163-206`); those route names exist. However search path filtering and context prefetch scoping have the limitations recorded in Phase 7.
- [FACT] The direct `record_fact` method writes `memory_type="semantic"`, an agent source, and provenance without explicit `source_type` or `trust_level` (`sdk/memora_client.py:213-249`). [INFERENCE] In the canonical write pipeline the semantic guard sees empty trust metadata and does not reject it, after which the provenance default is set to `candidate` (`core/memory/pipeline/write_service.py:203-223,330-359`). This is a concrete contract path that can produce candidate-trust semantic records; Phase 12 can confirm with a synthetic write.
- [FACT] `EcosystemMemoryAdapter.format_procedural_skill()` constructs an initial `VERIFIED` record with caller-provided provenance and no required evidence (`adapters/ecosystem.py:49-81`); the `MemoryRecordCreate` shape allows this (`core/memory/schemas.py:85-107`). [INFERENCE] If an integration sends this DTO to the legacy `/memories` write route, it aligns with the direct-lifecycle bypass from Phase 6 rather than the v1 pipeline's active-state default. The builder itself is not a network route and is not runtime-wired.

## Cross-agent acceptance notes

- [FACT] Specialized adapter code adds convenience namespace and provenance conventions, but the role labels do not become capabilities; server authorization depends on credentials, resolved Agent rows, namespace policy and grants (`adapters/*.py`; `core/policy/engine.py`).
- [FACT] The AI Universe adapter's identity is `ai_universe`, which is configured in the registry but absent from the API credential map; conversely `inference`, `stratex`, `cortex` and `memora` have server credentials but no adapter-config entries (`adapters/adapter_config.yaml`; `apps/api/dependencies.py:57-67`).
- [FACT] The Python distribution uses setuptools with no explicit package-discovery configuration (`pyproject.toml:1-4`). A wheel build from clean tracked `HEAD` fails flat-layout discovery because of multiple top-level packages (Phase 0), so the SDK/adapters are not demonstrated as an installable published package in this checkout.
- [FACT] No API calls were issued to the SDK's default hosted service. Existing tests inject a local `TestClient` or mock transport; actual third-party agent deployments were not contacted.

## Exit check

- [FACT] The repository contains useful client/DTO examples, but not one coherent, fully aligned installed SDK: adapter identity configuration differs from accepted API principals, constructor auth behavior differs between clients, and both outcome clients target a non-existent route contract.
- [FACT] Phase 9 is complete; next is resilience, reflection, collaboration and observability.
